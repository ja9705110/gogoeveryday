## 這一堂的主軸：攝影，不是剪輯

| | 分鐘 | 佔比 |
| --- | --- | --- |
| **攝影相關**（想主題、腳本、分鏡、景別、故事感、運鏡、正式拍攝） | **280** | 82% |
| 剪輯（InShot） | 40 | 12% |
| 成果與檢視 | 20 | 6% |

全課主軸：**先想 → 再寫 → 再畫 → 再拍 → 最後才剪**。
上午 170 分鐘全部在「想」，下午 170 分鐘全部在「做」，
其中正式拍攝實作佔 **75 分鐘**——這是整天最長的一段。

InShot 只教「把拍好的素材組成一支能看的影片」所需的九個步驟；
速度、濾鏡、貼圖、子母畫面列在講師備忘的「進度快可以補充」，不排時間。

## 流量：一支不夠，要有系列

依授課者指示新增的三頁，前後呼應：

- **第 8 頁**（PART 1）先埋伏筆：十一種主題不是挑一種拍一次，是**十一條可以一直拍下去的路**。
- **第 79 頁** 收回來：流量來自累積不是單支爆紅；觀眾要「知道下次看得到什麼」才會追蹤；
  系列化對自己的好處更大——**不用每次重新想題材**。建議選 **2–3 個系列輪流**。
- **第 80 頁** 落地成一張**四週發片計畫表**（一週一支就夠，同系列的影片開頭要長得像）。
  附錄③ 有空白版讓學員帶回家填。

## 貫穿全課的兩個數字

- **一顆鏡頭 3–5 秒**（實際錄 6–8 秒，前後各留一秒，剪掉頭尾剛好）
- **一支影片 15–30 秒**，大約 5 顆鏡頭

## 課前準備

**請學員事先想好：這次想拍什麼短影片？**

**攜帶物品**：手機／手機腳架／補光燈（有再帶）／要拍的商品或作品／
1–3 樣相關配件道具／充電線或行動電源

**事先完成**：手機充飽電、確認儲存空間、**安裝 InShot**

> ⚠️ InShot 一定要課前裝好。三十人現場下載會癱瘓教室 Wi-Fi，
> 中高齡學員裝 App 平均超過 10 分鐘，會直接吃掉剪輯段僅有的 40 分鐘。

## 上課前要確認的三件事

1. **InShot 版本**。介面改版快，**課前一週用自己的手機走一次九個步驟**。
   簡報第 66 頁已寫明「App 會改版，重點是知道要找什麼」，現場不一致就抓學員手機投影。
2. **音樂版權**。第 72 頁已加提醒：內建音樂多數可商用，自行加流行歌
   發到社群可能被消音或整支下架。
3. **成果怎麼收**。第 76 頁規劃為「兩兩互看 ＋ 挑 3–5 支投影」，
   三十人全部投影會超時。

## 改內容

```bash
python3 build.py     # 把 src/ 組成 index.html
node audit.mjs       # 檢查有沒有頁面爆版
node shot.mjs        # 每頁截圖到 shots/
node sheet.mjs       # 全部頁面的縮圖總覽 preview-all.png
```

- `src/shell.html` — 外框與樣板
- `src/styles.css` — 全部樣式
- `src/art.js` — 插畫與模擬元件庫（`ART.scene` 場景模擬、`ART.shot` 景別、
  `ART.move` 運鏡、`ART.board` 分鏡表、`ART.inshot` InShot 介面、`ART.vshot` 直式影格）
- `src/slides-a.js` — 第 1–44 頁（PART 0–5）
- `src/slides-b.js` — 第 45–64 頁（PART 6–9）
- `src/slides-c.js` — 第 65–84 頁（PART 10–11、附錄）
- `src/engine.js` — 翻頁、轉場、總覽、備忘、計時器

## 匯出 PPTX

```bash
node export-canva.js          # 產生靜態版面
node export-pptx/extract.mjs  # 量測並拆成 shape / image / text
node export-pptx/build.js     # 組出 pptx
```

匯出結果：**文字框 982　圖形 1,404　圖片 149**。文字全部 ≥ 15pt。

## 照片版位

簡報裡的插畫都是內嵌 SVG／CSS 畫的（離線可用、不連外）。
要換成實拍照的位置，在 `src/` 裡找 `ART.slot(...)`，整塊換成 `<img>` 即可。
